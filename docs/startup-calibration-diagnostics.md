# 上电校准进度为零：诊断版 caldiag3

这份改动用于定位故障，尚未确认反馈者板子的具体故障原因。校准阈值、400 样本要求、滤波和绘图逻辑保持原行为。没有使用超时跳过校准或强行置姿态有效。

## 当前证据

反馈者确认：固定板子并完全静止，断电重启后仍卡在校准页。

截图中 `cal=0`、`valid=0` 持续出现，但 `raw_g` 大致为 `-0.298,-0.375,0.917`，模长约 1.035g，处于现有 0.85–1.15g 校准范围内。加速度数据有更新，不能据此判断整个 IMU 未识别。`cal_ui=0`、`cal_id=0` 表示这张截图处于上电等待，并非一次尚未确认的手动按键校准请求。

旧版日志没有输出陀螺仪和校准拒绝原因。因此不能仅凭截图区分陀螺仪静止偏置过大、读数变化过大、短暂失读或采样中断。稳定的每秒加速度截图也不能排除采样间出现的瞬时异常。

## 安装和反馈

1. 使用 `Attitude-Indicator-v0.2-USB-Installer-r5.zip`，解压后在电脑 Chrome 或 Edge 打开 `安装器.html`，照常安装。
2. 保持 「清除设备数据」 不勾选。安装完成后关闭安装窗口，串口自动交回诊断。
3. 点击顶部「设备诊断」。已安装的设备会沿用连接；尚未连接时点击「连接设备」，首次选择串口，页面按 115200 自动读取。
4. 固定板子，保持静止约 10 秒。网页显示校准进度、三轴陀螺仪、加速度模长、采样率及中文原因；点击「导出诊断报告」，把得到的文本文件反馈。
5. 「查看示例」使用明确标注的模拟数据；连接实机时会清空示例。已有串口日志可通过「导入日志」离线分析。所有数据仅在本地处理，不上传。

同页安装和诊断共用连接，安装时暂停诊断读取，关闭窗口后恢复。请关闭 Arduino 等其他串口监视器。安装包只需一个离线 HTML；浏览器仍需用户首次亲自选择串口，USB 拔出或系统重新枚举后可能需要重新选择。

诊断版启动会输出 `Calibration diagnostics: caldiag3` 前缀。正常运行、等待校准或传感器发生故障时，每秒尝试输出一条独立短日志，避免原性能日志过长被串口窗口裁掉。日志依然采用零等待发送；串口未连接或缓冲不足时跳过，不阻塞仪表。

示例（仅示意，并非反馈者实测）：

```text
IMUDIAG v=caldiag3 present=1 fault=0 valid=0 cal=0/400 peak=0 reject=600 reason=gyro_rate gyro_dps=11.459,0.000,0.000 g=1.035 hz=200.0 invalid=0 gaps=0 age_ms=5
```

## 字段

| 字段 | 含义 |
| --- | --- |
| `present` | IMU 初始化是否成功 |
| `fault` | 最近样本/积分是否异常；不等于已经校准 |
| `valid` | 经过初始化、校准、故障和新鲜度检查后的姿态是否有效 |
| `cal` | 当前稳定样本数 / 400 |
| `peak` | 当前校准请求内曾达到的最大样本数 |
| `reject` | 当前校准请求内被稳定性条件拒绝的样本/采样块次数 |
| `reason` | 最近一次稳定性条件拒绝的原因；在继续累计时保留，成功或新校准请求时清除 |
| `gyro_dps` | 经当前安装方向映射后的三轴原始陀螺仪，单位 °/s，尚未扣除零偏 |
| `g` | 三轴原始加速度模长，单位 g |
| `hz` | 上一日志间隔中的有效样本频率 |
| `invalid` | 运行以来失效读数次数，包括 I2C 失读/饱和，并非专指总线错误 |
| `gaps` | 运行以来超过 100ms 的采样中断次数，同一次中断不反复累计 |
| `age_ms` | 最近有效读取距今时间；未有样本时为 0，应结合 `hz`、`present`、`fault` 判断 |

| `reason` | 当前代码拒绝条件 |
| --- | --- |
| `none` | 尚无稳定性拒绝记录，或已完成校准/刚发起新请求 |
| `nonfinite` | 加速度或陀螺仪存在 NaN/Infinity |
| `gravity_range` | 加速度模长不在 0.85–1.15g 开区间内 |
| `gyro_rate` | 三轴陀螺仪合成速率超过 5°/s |
| `gyro_variation` | 4 样本平均陀螺仪与累计均值的合成差超过 0.75°/s |
| `accel_motion` | 单样本或 4 样本均值的重力向量变化超过现有阈值 |

`reason=gyro_rate` 不自动证明硬件零偏大：转动、异常读数也能触发。应结合固定静止状态下连续的三轴速率判断。不要在取得这份数据前单纯放宽校准门槛。

## 验证范围

主机测试覆盖截图重力向量可完成校准、不同拒绝条件、进度为零时的诊断计数、失读恢复和短日志输出。诊断包需要反馈者在故障板上复测；主机测试和成功编译不代表该板的问题已经解决。

网页串口生命周期参考：[Chrome Web Serial 官方说明](https://developer.chrome.com/docs/capabilities/serial)。网页回归覆盖分包、旧日志、状态恢复、断开/过期、导入导出、示例隔离、内存容量和 reader 释放后关闭端口。

## caldiag3 硬件检查

诊断连接开启目标 20 Hz IMU 数据和 1 Hz 硬件快照，网页显示实际收到的更新次数。依次保持固定静止、采集 10 秒数据、运行 IMU 内置自检和内存/程序检查，再导出报告。

IMU 检查覆盖预期地址 0x6B 的身份、控制寄存器、温度、时间戳与细分读取计数；预期地址异常时还会只读探测 0x6A，提示可能的板型或地址差异。自检结果区分响应不足、通信失败、超时及配置恢复问题。自检结束后会重新校准，原校准条件没有放宽。

电源管理使用低频 ADC；不能测纹波。内存检查仅覆盖临时 RAM 最多 16 KB（连续空间不足时缩小）、PSRAM 最多 64 KB，运行程序镜像校验不代表 Flash 全盘检查。设置存储只检查能否打开，不写测试数据。触摸、按键、显示的接口活动需结合人工操作确认实际功能。一次自检失败仍需排除通信、供电等原因后判断硬件损坏。
