# 运行后卡顿与安装方向修订

2026-09-09，ESP32-S3 实物验证。

## 原因与修复

1. Arduino ESP32 3.3.10 的 HWCDC 默认发送等待为 100 ms；发送重试最多 20 次。显示循环每秒调用 `Serial.printf`，电脑停止读取时可能在日志发送中等待数秒。旧版 `frame_ms` 在日志发送之前取值，不能反映这次卡顿。
2. 设置 HWCDC 发送等待为 0，先检查容量，只发送完整的可容纳日志，否则丢弃。没有在显示循环中等待日志队列腾空。`max_gap_ms` 记录相邻显示循环的最大间隔，包含上一轮日志处理；`drops` 记录丢弃次数。
3. 线段距离计算把除法移出逐像素循环，完全覆盖的像素直接赋色，只有边缘做开方与透明混合。
4. 黄色标记、支柱和底座的几何操作在开机时由代码生成并缓存。逐帧重放保留原有顺序和抗锯齿，绘图循环不分配内存。
5. 球面背景采用 Q18 定点增量计算，避免每个像素反复浮点计算。使用 O3 优化绘图翻译单元，不启用 fast-math。

分别测试过交错存放查找表、逐行复制背景到内部内存、额外 DMA 分块搬运。这些方案在实物上没有收益或出现退化，最终版本均未保留。仍使用官方 GFX 原有的同步整帧 RGB565 传输。

## 轴向

用户确认屏幕正对观察者、USB 在左侧且竖直：传感器 X 约 +1g；用户随后确认屏幕朝上平放：Z 约 −0.97g。画面黄色箭头在 12 点方向，无需旋转画面。

航模右手坐标系为 X 进入面板、Y 向右、Z 向下。对应 `toBody = {sensor.z, sensor.y, -sensor.x}`，加速度和角速度使用相同映射。单元测试覆盖零位、正俯仰、正横滚、朝上平放及右手性。校准应在默认竖直安装姿态进行。

## 验证

- 原生姿态、绘图、USB 满缓冲和安装轴向测试通过，ASan/UBSan 无错误。
- 与旧版比较六个姿态，最大平均 RGB565 三通道绝对差合计为 0.002735 / 125，差异集中在地平线抗锯齿边缘；水平姿态完全一致。
- 独立代码审查未发现新内存或整数溢出问题。
- 中间优化版停止串口监视约一分钟，`drops` 从 17 增至 75，`max_gap_ms` 保持 138.0，采样约 200 Hz、内存不变。最终版记录见 `docs/validation.md`。

日志保留在 `build/serial-profile.log`、`build/serial-stages.log`、`build/serial-math.log`、`build/serial-cached.log`、`build/serial-soak-interim.log`。这些是各轮诊断版本，最终固件以最新烧录校验和清单为准。
