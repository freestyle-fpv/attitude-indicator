- 水平、正俯仰、正横滚与陀螺仪积分方向。
- 横滚经过倒置、长期积分数值稳定性。
- NaN/Inf、非法时间步长、过大加速度的处理。
- 连续静止样本要求、零偏均值、旋转与重力方向变化时重启校准。
- 有固定安装倾角时，纯航向变化不会产生假俯仰/横滚。
- 绘图圆外黑色、下半圆填充、固定飞机标、天空/地面与姿态方向。
- 白色横滚刻度移动、外圈地平线不受俯仰影响、±180° 横滚连续性。
- 已知 I2C 故障及传感器饱和立即使数据无效：代码路径审查通过，此硬件异常路径尚未上板注入测试。

## 审查修复

1. 安装校准四元数的乘法顺序：先增加可复现失败的测试，改为在右侧消除固定安装旋转，测试通过。
2. 区分传感器“暂未就绪”和“已知无效”：短暂饱和/读取失败立即清除校准有效性，不继续积分缺失的运动。
3. 白色横滚刻度跟随横滚转动，黄色指针保持固定。
4. 外环恢复参考图的直线地平线；预览图片采用自适应高度，防止在窄窗口中被拉成椭圆。

最终独立代码审查无新增可操作问题，详见 `docs/firmware-review.md`。

## 历史版本：右上角实时 FPS

新增 `FpsCounter` 与 `FpsOverlay`。每帧屏幕传输完成后计数，按不少于一秒的实际经过时间计算 FPS，包括任务等待、传输和日志处理间隔；不将传感器 200 Hz 采样率误报为屏幕帧率。启动首个统计窗口显示 `--.- FPS`。

## 第一轮：FPS 吞吐优化（历史版本28.6FPS）

## 第三轮：圆形紧凑缓冲、三阶段并行与硬件传输边界

本轮开始于2026-09-09，最终验证跨至09-10。保留466×466完整圆形图像、已确认的USB左侧安装映射、200Hz采样与实际完整帧FPS。

背景阶段在CPU0优先级1读取不可变PSRAM表，前景在CPU1绘制刻度及固定图形，CPU0优先级2发送DMA；IMU优先级3。三个缓冲按free→background→ready→foreground→display→free流转，仅显示任务在传输完成或丢弃后归还。整帧捕获一次姿态，校准/故障时清屏一次并丢弃该帧剩余带，最后一带完成才计一帧。背景每帧显式让出1tick，状态页及丢弃路径也让出，SPI初始化/ISR/发送继续保持CPU0同核。

每带取包住所有圆内像素的偶数列矩形，绘图直接使用该矩形的列偏移和步长；不再绘制、复制或传输多余的恒黑角落。初始与状态转换全屏清黑，状态图形均在圆内。FPS/DEMO按相同偏移合成。完整466步长接口继续供本机预览与参考测试使用。

常用命令缓存与固定图形优先使用片内内存，分配前为随后创建的队列/任务保留64KB，不足时回退PSRAM。背景大表仍在PSRAM，无每帧分配。背景与前景的render_ms是两个阶段经过时间的总和，阶段会交叠且可能被抢占；吞吐以frame_ms和FPS判断。

QSPI窗口命令与像素通过同一SPI设备发送，使用官方Espressif驱动同样的0x32/0x2C像素RAMWR格式。设置原生窗口后使vendor窗口缓存失效，校准页恢复原生绘图时会重新设置窗口。公开CO5300资料的写入周期至少20ns；本机S3整数分频请求50MHz仍是40MHz，继续使用40MHz。

大块DMA实验曾触发硬件长度拒绝并重启，已修复：单次像素数同时受库分配和SPI_LL_DMA_MAX_BIT_LEN/16限制，最多16384像素（32768字节）。build_opt.h设置ESP32QSPI_MAX_PIXELS_AT_ONCE=2048，库总线容量32776字节。构建脚本发现全局选项改变时执行干净重编译，避免Arduino复用旧vendor对象。最终稳定性以修复后的固件重新检查，实验失败不计入最终结果。
