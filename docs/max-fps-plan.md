# 提高实际显示帧率

授权：用户要求开始优化 FPS、尽可能高；延续已授权实物烧录。保留 466×466 完整圆形 UI、实时 FPS、USB 左侧轴向与 200 Hz IMU。性能以真实完成帧率计，不降低分辨率来抬高数字。

1. 背景光栅独立优化：解析地平线与扫描线交点，连续天空/地面段从现有渐变表复制，仅对边缘执行原着色计算。与备份 renderer 进行多姿态图像比较。
2. DMA 独立优化：复用官方显示初始化，以第二个共享 SPI device 管理队列传输，增加块尺寸并交叠字节转换与 DMA。先保持 40 MHz；旧路径作为对照。完成后检查显示与真实采样率。
3. 若两项独立优化不足，使用双帧缓冲把渲染和传输放到独立任务；缓冲所有权明确，故障/校准屏只由一个任务写屏，显示队列不积压旧姿态。
4. 审查并实物测试：保持原画面，运动与演示测 FPS，关闭串口读取检查长帧、堆和采样率；最终烧录最佳稳定实现并更新清单。

备份：build/before-max-fps/。此目录无 Git，直接在已授权工作目录修改。

## 实测后调整

- 双 DMA 传屏：59 ms →23.5 ms，8.5→12 FPS。
- 解析背景：背景33→20 ms，完整约14.6 FPS。
- 双核心整帧方案：约21 FPS，但并行读取PSRAM使背景20→29 ms，复制10→20 ms；确认外部内存竞争。
- 决定改为两个466×80内部DMA带缓冲：同一帧捕获一次姿态，逐带渲染与发送；仅最后一带完成计为一帧。保持40MHz，不依赖提高硬件时钟。新的异常处理需要清屏一次并丢弃该帧剩余带。

- 分带初版触发 SPI 总线锁中断异常。将显示初始化放到 CPU0，使 SPI AUTO 中断与显示任务同核；随后连续运行约四分钟，覆盖动态姿态、演示及持续校准，未再出现重启。80 行版本静止约 25.4 FPS，运动约 23 FPS。
- 下一版改为 118/118/118/112 四带，两个内部 DMA 缓冲共 219,952 字节。渲染器直接输出屏幕字节序，去掉全帧字节转换；DEMO 标志也合成到带缓冲，避免每帧额外的轮询传输。

- 最终采用四带、直接屏幕字节序和姿态几何缓存。静止实测 28.6 FPS，演示约 24.4–28.6 FPS；保留原生分辨率与40MHz时钟，未声称所有姿态稳定30FPS。逐像素、溢出回退、编译、写入校验和动态/校准测试通过，详见 validation.md。

## 继续优化（第二轮）

用户授权继续提高FPS。以已验证28.6FPS固件为回退，备份build/before-fps-round2。实测剩余绘图31ms中刻度14–16ms；反汇编确认每个线段边界反复调用floorf/ceilf/fminf/fmaxf。先以屏幕坐标有限范围内的等价取整替换，百万坐标边界与多姿态像素对照验证后上板。后续只依据实测收益保留变化，继续保持原生分辨率及真实完整帧计数。

第二轮实测推进：

- 等价有限坐标取整：静止28.6→约30FPS，图像一致。
- 画线代码放IRAM：无收益且增加约10KB片内内存占用，已撤回。CPU实测240MHz。
- 周期计数表明准备阶段约0.6ms、像素循环约13.3ms，约35,000次像素检查/帧。
- 以抗锯齿支撑范围收紧包围盒：约16,000次检查，静止约34FPS。
- 对倾斜线按扫描行裁剪无限条带：约9,600次检查，保留圆端点与浮点余量，画面像素不变。
- DMA队列从2增至8，当前每条显示带的7个事务可以全部排队；更长传输仍按FIFO安全复用。
- 临时周期计数已移除。最终编译480,014字节程序/34,348字节静态RAM；最终实测见validation.md第二轮记录。

第二轮最终正常姿态约34.6FPS，比上一轮约提高21%；动态演示29.7–34.5FPS。源码回归检查、编译与烧录校验通过，持续校准恢复通过；最终无串口复查记录写入validation.md和固件manifest。

## 第三轮：实测可达到的性能边界

用户要求继续优化到没有可验证收益。保持图像、分辨率、真实整帧计数、IMU采样与已确认安装轴向。备份build/before-fps-round3。独立核对官方QSPI允许时钟；本地依次测窗口/总线开销、背景复制和数学处理、带尺寸和传输频率。每项保留需满足像素回归及实物收益；无收益则回退。最终用持续演示、校准、无串口运行验证，并记录剩余瓶颈；不能把有限实验称为数学上无任何优化可能。

第三轮阶段记录：官方Co5300 V0.01资料写入周期至少20ns；本机ESP32-S3 SPI只支持80MHz APB/XTAL及整数分频，请求50MHz仍得到40MHz，80MHz超出公开时序，因此不通过超出规格提高时钟。资料https://files.waveshare.com/wiki/common/Co5300_Datasheet.pdf (p107)，本地soc/clk_tree_defs.h与hal/spi_ll.h已核对。标准memcpy替代现有对齐字复制没有收益（约34.1vs34.6FPS），已回退。窗口/总线前缀约1.7ms每帧，正在测试同一SPI设备直接发窗口命令。

第三轮进度：直接同设备窗口命令约35.0FPS；有限取整在200万个坐标和199姿态精确对照通过后约35.3FPS。官方Espressif CO5300驱动使用0x32/0x2C直接携带像素，正在测试移除多余空RAMWR事务。进一步计划：比较118/94/78行带大小；按圆边界裁剪每带传输矩形，只减少原本恒黑的圆外角落，以像素重建测试确保可见区域完整。裁剪辅助代码及测试由独立子任务实现，板上测量继续由主任务独占串口。此目录无Git，保留可回退文件，不运行依赖Git的清理步骤。

分带实测（尚未裁剪圆外区域）：118行35.5FPS；94行35.3FPS，多一次几何/窗口遍历抵消了较短带的收益。下一项78行测试中。决定追加三阶段流水线实验：78行三缓冲（内存接近原118行双缓冲）；CPU0背景/CPU1前景/CPU0 DMA并行。请求一帧一次、背景独占申请空缓冲、前景消费准备队列、DMA完成后释放。背景/显示/IMU优先级拟为1/2/3，背景每帧让出1tick保证IDLE。背景不写全局绘图计时。收益需上板证明，否则回退双缓冲最佳版本。

圆外裁剪首测：memmove打包意外耗时约13ms，帧率退到26FPS。已改为向前对齐32位复制，并从ESP32反汇编确认生成load/store循环；108811条带几何、4280打包、72个整帧重建通过。三阶段API拆分完成；独立199姿态、乱序分带及多线程对照正在核验，背景只读查找表且不修改全局统计，前景单核维护几何缓存。固件481642字节程序/34364静态RAM，已编译、烧录校验，开始实测78行三缓冲。

三阶段实际有效：78行约39.6–39.9FPS，94行约40FPS，IMU仍200Hz。78行空闲堆85976，94行为41196字节。并发绘图导致各阶段自身耗时略增，但完整帧减少。决定继续让背景和前景直接生成圆形带的紧凑布局，移除DMA任务里剩余打包复制；Canvas索引、背景行和固定图形回放统一支持列偏移/步长，FPS/DEMO也按相同偏移合成。原466步长API保留，新的紧凑输出需与独立原图裁剪精确一致。随后重新比较小带尺寸，最终保持实测最佳配置。

紧凑绘图实测：94行约42.5FPS，78行约41.4FPS。所有203姿态/两种字节序/完整重建、并发、溢出测试通过；原图不变。追加热点数据内存实验：命令缓存改为独立分配，常用命令与固定图形优先片内内存，分配前保留64KB供后续队列/任务；不足则回退PSRAM。全部六个分配失败/重试、1325旧图对照和新增紧凑/并发测试通过。大背景查找表仍放PSRAM，无运行时分配。正在比较78行热点缓存版本，后续60/48行可让更多热点数据留在片内。

热点缓存78行校准后约42.9FPS，较同分带直接紧凑输出约41.4有收益；60行空闲堆约63720字节，静态固定图形阶段缩至约1.3ms。发现官方QSPI库的ESP32QSPI_MAX_PIXELS_AT_ONCE具有ifndef配置入口；通过ESP32 core支持的build_opt.h统一设4096，bus max_transfer_sz变65544字节，FastPanel按同一宏推导32768像素块，60行可整带一次DMA。额外库缓冲约12KB，保留内存储备。未修改vendor源，正在实测此最后一项DMA容量调整。

DMA边界实验遇到并已修复P1：32768像素虽然低于库分配容量，但超过ESP32-S3外设18位长度寄存器的262144bit上限，实际queue_trans拒绝并重启。最终改为min(库容量,SPI_LL_DMA_MAX_BIT_LEN/16)，最多16384 RGB565像素/32768字节；build_opt改2048，库容量32776字节且额外缓冲只约4KB。独立审查确认修复并无其他可操作发现。正在补实际FastPanel源的模拟SPI边界回归，后续稳定性以修正版重新测试，失败实验不计入最终结果。

构建一致性修复：检查发现Arduino在build_opt.h内容变化后仍复用旧vendor对象（QSPI对象时间戳停留在4096实验），导致库缓冲保留较大配置。tools/build.sh现在比较已应用的全局选项，变化时传--clean，成功后保存选项副本；确保库和应用统一重编译。当前从干净构建生成2048配置，DMA仍由库与硬件双重上限约束，失败实验固件已替换为稳定的32KB限制版本。

最后分带比较：48行静止约41–42FPS，演示51条统计36.4–41.0FPS、中位38.2；60行32KB限制版演示192条37.0–41.6FPS、中位38.8。较小带带来的窗口/调度成本抵消了圆外像素节省，因此选择60行（7×60+46）作为最终配置。最终库参数2048已干净重建，优于此前使用旧库缓存的内存占用；下面的最终稳定性测试会在该一致构建上执行。


第三轮完成：最终60行/三缓冲/紧凑输出/内部热点缓存/32KB双重限制DMA/40MHz。静止中位42.9FPS，较34.6约提高24%；演示37.2–41.8，中位38.8。所有像素、并发、内存失败、DMA上限、编译和烧录校验通过，持续校准恢复与167秒无串口复查完成。复查时手动大幅运动最低帧率见validation.md，恢复近水平约42.9；最长帧间隔保持108.5ms（包含此前校准转换），内存小幅52字节变化后稳定。已保留本轮测试中整体表现最佳的稳定配置，有限实验不能证明数学意义的全局最优。
