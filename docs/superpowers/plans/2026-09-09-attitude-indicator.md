# Attitude Indicator Implementation Plan

> Execute the approved design in this session. Use subagent-driven-development for the independently testable renderer while the main worker integrates hardware and sensor fusion. This is an empty non-Git project; work directly in the user-selected directory, without creating a second checkout or making commits.

**Goal:** A buildable ESP32-S3 466×466 round attitude instrument using onboard QMI8658, plus a preview rendered by the same C++ code.

**Architecture:** Pure C++ renderer and attitude filter have no Arduino dependency. Arduino board integration reads IMU samples in a dedicated task, publishes a mutex-protected attitude snapshot, and sends RGB565 frames through the official CO5300 driver.

**Tech Stack:** Arduino ESP32, official bundled GFX and SensorLib, native clang++ tests and preview, standard-library Python preview server.

**Spec:** `docs/superpowers/specs/2026-09-09-attitude-indicator-design.md`

## Global constraints

- 466×466 full circle. All instrument visuals generated by code.
- Fixed yellow aircraft, white pitch/bank markings, shaded blue sky and brown ground, complete bottom.
- Pitch positive nose-up; roll positive right wing down. Right roll rotates horizon counterclockwise.
- QMI8658 independent operation; no flight-controller protocol in this version.
- Explicit calibration/fault/demo states. No automatic demo fallback on sensor failure.
- Software verification and actual device testing reported separately.

### Task 1: Pure C++ renderer and shared native preview

Files: `firmware/AttitudeIndicator/renderer.h`, `renderer.cpp`, `tests/renderer_test.cpp`, `tools/render_frame.cpp`.

Interface:
```cpp
namespace instrument {
class Renderer {
 public:
  bool begin();
  void render(uint16_t* rgb565, float pitchDegrees, float rollDegrees);
};
}
```

- [x] Write pixel-behavior tests first: circular clipping, filled lower center, sky/ground swap under 180° roll, nose-up increases sky below center, aircraft stays fixed.
- [x] Run failing tests, then implement round sphere, curved pitch ladder, bank scale, fixed yellow marker and complete lower structure. No per-frame allocation; precompute expensive geometry in begin.
- [x] Compile native frame generator; `render_frame PITCH ROLL OUTPUT.bmp` emits a 466×466 BMP using the identical RGB565 renderer.
- [x] Inspect native rendered images, adjust visual fidelity, run renderer tests again.

### Task 2: Attitude fusion, calibration, board integration

Files: `firmware/AttitudeIndicator/attitude.h`, `attitude.cpp`, `board_config.h`, `AttitudeIndicator.ino`, `tests/attitude_test.cpp`, dependency setup scripts.

Interface:
```cpp
namespace instrument {
struct Vec3 { float x,y,z; };
class AttitudeFilter {
 public:
  void reset(Vec3 acceleration);
  bool update(Vec3 acceleration, Vec3 gyroRadPerSec, float dtSeconds);
  float pitch() const;
  float roll() const;
};
}
```

- [x] Verify official source pin map, power/reset initialization, accelerometer/gyro units and APIs; lock commit and toolchain.
- [x] Write meaningful fusion tests for level/tilted initialization, gyro integration, wrap continuity, invalid dt/data, normalization; observe failure before implementation.
- [x] Implement quaternion filter with acceleration magnitude gating; stationary gyro calibration rejects motion and retains time-based sample spacing.
- [x] Add configurable sensor-to-body axis mapping, task-separated sampling/display, BOOT calibration/explicit demo, serial diagnostics and fault state.
- [x] Build against actual ESP32 dependencies; resolve compilation errors and record output.
