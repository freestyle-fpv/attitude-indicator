# 设备硬件诊断 Implementation Plan

用户授权直接扩展当前离线安装/诊断程序。沿用现有 checkout，不提交或发布；使用系统调试、测试驱动和完成前验证流程。

**Goal:** 扩展可实施的板级诊断，优先定位 IMU 校准阻塞，并将实时网页数据由 1 Hz 提升至按需 20 Hz。

**Architecture:** I2C 仍仅由采样线程访问。被动巡检低频执行；主动 IMU 自检只在网页按钮请求后执行，所有等待有超时，结束后恢复传感器配置并重新校准。固件输出短行、零等待和有限诊断订阅租期。网页将硬件结果、静止统计和校准原因映射为中文，缺失/过期字段不能当作通过。

1. 测试并实现无 Arduino 依赖的自检状态机/响应解析、静止统计与内存图案检查工具；覆盖超时、I2C 失败、阈值、字节序和恢复。
2. 固件增加 IMU 身份/配置/温度、分项通信计数和三轴原始加速度，低频检查电源管理/触摸/扩展器，记录按键/触摸/显示同步与内存信息。新增手动 IMU 自检、RAM/PSRAM 小块图案和运行固件校验，保留原校准阈值。
3. 按需 20 Hz IMU 数据、1 Hz 设备信息；网页连接后发订阅心跳，断开停流，菜单内也能响应诊断。旧固件命令无副作用。
4. 网页标题改「设备硬件诊断」，增加中文分项结果与操作建议、静止窗口统计、主动检测按钮、范围说明和报告；控制台降频刷新、曲线保留有限历史。
5. 更新测试、编译、打包 caldiag3/r5；执行主机测试、模拟串口网页检查、离线与窄屏检查。物理行为未实际测试时明确说明，不把模拟结果当实测。
