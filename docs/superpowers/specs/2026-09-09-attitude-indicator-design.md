# 航模座舱圆形姿态显示器设计草案

状态：用户已批准并完成软件实现、测试和固件编译。使用板载 QMI8658 独立运行；实物验证尚未进行。

## 目标与视觉

为 Waveshare ESP32-S3-Touch-AMOLED-1.75 实现代码绘制的姿态仪。
参考用户提供的图片，补全下半部，使外轮廓成为完整正圆。
图片中的说明文字和控制面板只作为参考内容，不自动成为产品需求。

- 使用屏幕原生 466×466 坐标，圆心 (232.5, 232.5)，最大半径 232.5。
- 天空为蓝色，地面为棕色；用程序生成的明暗渐变表现内球面的层次。
- 白色地平线、俯仰刻度及数字；外圈上部绘制横滚刻度。
- 黄色飞机标固定在屏幕中心，保留参考图的机翼、中心圆点和下部弧形结构。
- 补全底部棕色球面、内圈轮廓及黄色支杆；支杆底座收在圆形范围内。
- 倾斜时天空、地面和俯仰刻度随姿态变化，飞机标保持固定。
- 水平姿态时地平线通过中心；抬头时地平线向下，右滚时地平线逆时针旋转。
- 参考图的截图裁切线不进入最终画面。正常仪表界面不摆放截图外侧的文字和滑块。

## 实现方案比较

1. **推荐：Arduino C++ + 自定义绘制 + 官方显示驱动。** 适合以单个动态仪表为主的界面，渲染和数据采集边界清楚。
2. Arduino + LVGL 自定义画布。若后续需要大量触摸菜单，控件管理更方便，但单仪表会增加集成成本。
3. ESP-IDF + 自定义绘制。任务调度和显示传输控制更细，首版构建配置较多。

首版建议采用方案 1，沿用官方 CO5300、AXP2101 和 IO 扩展初始化方式。
依赖版本以选定的官方仓库提交及其构建配置为准，并记录版本；不混用旧文档库和新示例。
文档页面列出的 Arduino core 3.1.0 与当前仓库列出的 3.3.10 不同，需要在实现时锁定一致组合。

## 模块与数据流

- `board`：显示、电源、I2C、按键等板级初始化，硬件引脚以官方示例和原理图核对。
- `attitude`：提供姿态四元数、时间戳及有效状态；可接板载 IMU 或未来的外部飞控输入。
- `renderer`：从姿态计算圆形画面，绘制所有形状与刻度，不使用仪表截图贴图。
- `app`：处理启动、采样、显示更新、校准及显式进入的演示模式。

首版数据流：QMI8658 加速度和角速度 → 轴向映射与静止校准 → 四元数融合 → 渲染器。
安装朝向应可配置；校准须拒绝明显运动中的样本。实际安装后确认抬头和横滚的符号。
外部飞控通信不在首版实现范围内。
演示姿态独立于实际数据，数据异常不会自动切换演示。

## 性能与异常

首版目标显示约 30 帧/秒，最终帧率以开发板实测为准。
一帧 RGB565 缓冲需要 434,312 字节，两帧共 868,624 字节；帧缓冲优先放 PSRAM。
利用查找表和预计算减少逐帧三角函数开销；QSPI 发送使用驱动支持的缓冲及同步方式。
采样与显示按时间调度，避免显示速度决定滤波时间步长。
初始化失败、数据超时和校准未完成须有明确状态，不能把无效数据当成水平姿态。
